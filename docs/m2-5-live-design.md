# M2.5 live-test preparation decisions

2026-10-19, before implementation. This change prepares an interactive synthetic MCP test. No accounts, remote resources, deployment, exposure, ChatGPT connection or schedules are created.

- Reuse the agent resource server and strict JWT validation. Choose Auth0 authorization code + PKCE S256, a predefined client, RFC 8707 resource compatibility and RFC 9068 RS256 access tokens. No home-grown authorization server, bearer-token prompt or LLM API. Provider login, consent and code exchange remain provider responsibilities.
- Use only `academic-opportunities-agent-poc` and `academic-opportunities-agent-poc-db`. Generate a separate ignored Wrangler file offline; require UUID/name/account verification before every remote operation. No R2, Queue, Email, assets, routes, service bindings, cron or production/demo generator changes.
- In `APP_ENV=poc`, expose only `/mcp` and protected-resource discovery. Existing local REST rehearsal remains available in local mode. Add a hard UTC test-window expiry, bounded to seven days during configuration, so an abandoned endpoint fails closed. Preserve issuer/audience/user/client/scopes, quotas, byte limits and private result states.
- Bootstrap only the compiled three fixture identities with verified MIME/text hashes. Record explicit synthetic bootstrap provenance in a new append-only private table, not fake successful M2 integrity jobs or nonexistent stored MIME. The inherited non-null `messages.r2_key` is a `synthetic-no-object/` sentinel, never an object location. Only PoC mode may use this separate provenance; local M2 flow continues to require actual integrity jobs. Bootstrap is one transactional SQL execution, idempotent and tombstone-aware, with no public setup endpoint. Do not reset claims/results to repeat a trial: recreate the isolated PoC database after authorized cleanup.
- Remote commands require an action-specific confirmation environment variable, validated exact config and Cloudflare D1 name/UUID metadata. Initialization additionally refuses unexpected data, existing M2 jobs/outbox/attachments or public opportunities. These are guardrails, not a substitute for user approval. Nothing remote runs in CI.
- Verify stored results privately via D1, including actual strict schema/evidence, counts, IDs and zero publication. A metadata probe only checks discovery, unauthorized denial and route closure; it does not prove OAuth or model extraction. Acceptance must include an actual ChatGPT trace plus D1 receipt.
- Restrict Auth0 with a dedicated tenant/app, no self-signup, one allowed user subject, a fail-closed post-login Action and short tokens. Disable refresh for this interactive experiment; scheduling remains outside scope. No client secrets are needed in the Worker; if a confidential OAuth client is required by the available UI, enter its secret only in provider/ChatGPT authentication settings.
